StockAnalyst는 Spring Boot + React(Vite) + Python 파이프라인으로 만든 주식 정보 서비스다. 개발기 1편은 뉴스 감성 모델과 종목 추출이었고, 2편은 그것을 뺀 나머지를 주제별로 나눴다. 전체 목차는 개발기 (2) 목차에 있다.

한눈에 보기

  • 1차 추세는 일봉 좌우 5일 극값이 아니라 **주봉 + ZigZag 5%**로 잡는다. 같은 1년치에서 33개가 4개가 된다
  • 두 지수가 같은 방향이면 상호 확증, 엇갈리면 전환 경고. 여기에 52주 위치를 더해 9국면을 붙인다
  • 횡보에 국면 이름이 없어 코스피가 늘 "판독 보류"였다. 계산은 맞는데 결과에 이름을 안 붙여 둔 것이 화면에선 오류로 보였다
  • 52주 레인지가 3.7배로 벌어지면 선형 위치는 거짓말을 한다. 고점 대비 −32%가 "한가운데 56%". 로그로 바꾸니 70%
  • 낯선 자릿수를 데이터 오염으로 의심했다가 연속성·실제 등락률·역산 셋으로 정상임을 확인했다

우하단 플로팅 버튼 📊 시황 분석을 누르면 국내(KOSPI·KOSDAQ)와 미국(S&P 500·NASDAQ) 두 시장의 1차 추세와 국면이 뜬다. 백엔드는 DowTheoryService 하나, 엔드포인트는 GET /api/v1/market/dow-theory다.

중요한 성질이 하나 있다. 외부 호출이 0이다. 이미 쌓아 둔 stock_candle_daily의 대표 ETF 캔들만 읽는다. KIS 호출 한도와 아무 관계가 없어서, 사용자가 몇 번을 열든 외부 API 예산을 안 쓴다.

2. 판정 파이프라인

지수 하나를 이렇게 처리한다.

주봉으로 집계하는 이유

toWeekly()는 ISO 주 기준으로 high=max / low=min / close=마지막 / vol=합으로 묶고, 종가가 없거나 0 이하인 미완성 봉은 버린다.

다우의 1차 추세는 수개월 단위다. 일봉 잡음을 그대로 넣으면 판정이 매일 흔들린다. 처음엔 일봉의 좌우 5일 극값을 스윙점으로 썼는데, 잔파동이 전부 잡혀서 HH/HL(고점 상승·저점 상승) 판정이 하루 걸러 뒤집혔다.

ZigZag 5%

직전 전환점 대비 5% 이상 반대로 움직여야 스윙 고/저점을 확정한다. 고점→저점이 교대로만 기록되고, 응답에는 최근 8개만 싣는다.

같은 데이터인데 후보가 33개에서 4개가 된다. 33개짜리로는 "지금 고점이 올라가고 있나"라는 질문에 매일 다른 답이 나온다. 4개짜리로는 답이 몇 달에 한 번 바뀐다. 다우가 말하는 1차 추세는 후자 쪽 시간 단위다.

같은 필터를 변곡점 모델의 정답 라벨에도 쓴다. 쓰임은 완전히 다르지만 "어디가 스윙 고저점인가"를 정하는 도구는 하나로 통일했다.

추세 판정에는 우선순위가 있다

거래량 확증 — 횡보에는 확증 개념이 없다

최근 13주 중 상승주의 평균 거래량과 하락주의 평균 거래량을 비교한다. 상승 추세면 상승주에, 하락 추세면 하락주에 거래가 실려 있어야 확증이다.

문제는 횡보다. 어느 쪽에 실려야 맞는지가 정의되지 않는다. 그래서 횡보에서는 volumeConfirms를 아예 내려보내지 않고, volumeRatio(상승주 평균 ÷ 하락주 평균)만 참고값으로 표시한다. 판정할 수 없는 걸 판정한 척하는 것보다 숫자만 보여 주는 게 낫다.

확증이 났어도 어느 한쪽 거래량이 안 붙으면 "강도는 약할 수 있습니다"를 뒤에 덧붙인다.

코스피↑·코스닥↓처럼 엇갈리는 날이 잦아서, 나중에 지수 4개 각각에도 자기 추세·자기 국면·자기 사이클 그래프를 주는 구조로 바꿨다. 시장 쌍의 판정과 개별 지수의 판정을 둘 다 본다.

4. 국면

phaseFor(direction, pos, volWeak) 함수 하나가 시장 쌍과 개별 지수를 모두 판정한다. pos는 52주 고저 구간에서 현재가의 위치(0~1)다 — 이 값을 어떻게 재는가가 6절의 주제다.

시장 쌍의 direction은 signal에서 온다. CONFIRMED_UP→UP, CONFIRMED_DOWN→DOWN, DIVERGENCE→TRANSITION, UNCLEAR→SIDEWAYS. 개별 지수는 자기 추세를 그대로 쓴다.

directionposkey라벨
UP< 40%ACCUMULATION축적기 (1국면)
UP40~75% + 거래량 확증PARTICIPATION대중 참여기 (2국면)
UP그 외DISTRIBUTION분산기 (3국면)
DOWN> 60%DIST_TOP하락 초기 (분산 후)
DOWN25~60%PANIC공포·하락 확산
DOWN< 25%DESPAIR침체·바닥권
TRANSITION—TRANSITION전환 국면
SIDEWAYS< 30%RANGE_LOW바닥 다지기 (축적 가능성)
SIDEWAYS30~70%RANGE_MID박스권 · 방향 대기
SIDEWAYS> 70%RANGE_HIGH고점 다지기 (분산 가능성)
UNKNOWN—null국면 판독 보류

국면이 없는 경우는 캔들 부족(UNKNOWN) 하나뿐이다. 이 문장이 지금은 당연해 보이지만, 원래는 그렇지 않았다.

추세가 있을 때는 이 곡선 위 어디쯤인지를 마커로 찍는다. 전환·박스권 계열은 사이클 상 위치를 특정할 수 없어서 마커 대신 안내 문구를 넣는다 — 특히 RANGE_MID는 "여기라고 말할 수 없다"가 정확한 답이다.

5. 코스피가 늘 "국면 판독 보류"였다

증상 — 코스피 카드에 계속 국면 판독 보류가 떴다. 사이클 그래프에 마커도 없고 매수 가이드 박스도 통째로 안 나왔다.

원인 — phaseFor가 UP / DOWN / TRANSITION 세 가지만 처리하고 나머지는 전부 null로 떨어뜨리고 있었다. 당시 코스피는 고점 146,614 → 110,060(LH), 저점 80,056 → 98,090(HL)인 수렴 구간이라 SIDEWAYS였고, 주봉 이평도 위아래 어느 쪽으로도 정렬되지 않았다.

데이터도 정상이고 계산도 정상이었다. 결과에 이름을 안 붙여 둔 것이 화면에서는 고장으로 보였을 뿐이다. 이런 버그는 예외도 로그도 안 남기기 때문에 스택 트레이스를 아무리 봐도 안 나온다.

수정 — SIDEWAYS 분기를 추가하고(RANGE_LOW / RANGE_MID / RANGE_HIGH), 시장 쌍의 UNCLEAR도 NONE 대신 SIDEWAYS로 넘긴다(지수 중 UNKNOWN이 있을 때만 NONE). 프론트도 DowPhase 유니온에 3개를 더하고 PHASE_INFO에 새 국면 3개 **+ TRANSITION**을 채웠다 — 전환 국면도 가이드 박스가 비어 있던, 같은 구멍이었다.

열거형에 값을 추가할 때 그 값을 소비하는 표를 같이 안 채우면 이렇게 된다. 백엔드에는 있는데 프론트 사전에 없는 키는 조용히 빈 화면이 된다.

6. 52주 위치를 선형에서 로그로

위 수정을 확인하다 더 큰 게 드러났다.

문제 — 2026년 코스피 대표 ETF의 52주 레인지가 40,900 ~ 152,148, 3.7배다. 현재가 103,500은 52주 고점 대비 −32%인데, 선형 위치로 재면 **56%**가 나온다. 화면에는 "한가운데 박스권"으로 읽힌다.

−32%인 가격을 "한가운데"라고 말하는 지표는 지표가 아니다.

수정 — logRangePos() 헬퍼를 만들어 analyzeGroup(시장 쌍)과 trendOf(개별 지수) 두 곳의 pos를 교체했다.

Math.log(px / lo) / Math.log(hi / lo)

가격은 덧셈이 아니라 비율로 움직인다. 40,900에서 81,800으로 가는 것과 76,074에서 152,148로 가는 것은 둘 다 2배인데, 선형 자에서는 앞쪽이 훨씬 짧은 거리로 보인다. 등락률 기준으로 재는 게 맞다.

같은 값이 **70%**가 되고 RANGE_HIGH(고점 다지기)로 떨어진다. 저점이 0 이하이거나 고저가 뒤집힌 비정상 데이터는 선형으로 폴백하고, 레인지가 좁으면 로그와 선형이 자연히 수렴하므로 평소 장에서는 값이 거의 안 바뀐다.

프론트 라벨도 고저 레인지 56% → 52주 위치 70%로 바꾸고 로그 스케일이라는 설명을 툴팁에 넣었다. 숫자의 의미가 달라졌는데 라벨이 그대로면 더 헷갈린다.

경계에 앉은 값을 어떻게 할 것인가

지금 코스피는 정확히 RANGE_MID/RANGE_HIGH 경계(70%) 위에 있다. 52주 저점을 40,00043,000 사이 어디로 잡느냐에 따라 69.571.2%로 흔들리고, 작년 여름 저점이 260거래일 창 밖으로 밀려나는 것만으로 라벨이 뒤집힐 수 있다.

경계를 옮겨서 원하는 답이 나오게 맞추지는 않았다. 어느 값으로 옮겨도 그 선 위에 앉은 시장은 똑같이 흔들린다. 그건 임계값이 잘못 잡힌 게 아니라 단일 임계값 방식 자체의 한계다. 대신 화면에 52주 위치 70%를 그대로 노출해서, 왜 그 국면인지를 사용자가 직접 보게 했다.

거슬리면 선택지는 둘이다. 경계 ±3%p 구간에 "경계" 표시를 붙이거나, 이전 판정을 기억하는 히스테리시스를 넣는 것. 후자는 상태를 저장해야 해서 아직 안 했다.

7. 미국 지수 종가가 NULL로 들어오던 버그

미국 장 마감 전(KST 새벽)에 수집하면 yfinance가 당일 미완성 봉을 NaN 종가로 준다. nasdaq/addStockCandleData.py가 그대로 INSERT해서 SPY/QQQ의 최근 캔들이 close=NULL이 됐고, 현재가가 0으로 읽혀 QQQ가 횡보 → UNCLEAR → 국면 보류가 됐다.

위치수정
수집기close_price.notna() & > 0 필터. NaN이면 INSERT하지 않음
서비스마지막 유효 종가로 현재가·이평 계산 (0/NaN 스킵)
기존 데이터DELETE FROM stock_candle_daily WHERE close_price IS NULL 후 --only nasdaq 재수집

세 번째가 함정이다. 증분 수집은 "DB의 마지막 날짜 이후"만 받으니, NULL 종가라도 행이 있으면 그날은 이미 받은 것으로 취급돼 영영 안 채워진다. 삭제가 필수였다.

같은 함정을 뒤에 공매도 잔고에서 한 번 더 밟는다. 증분 설계 쪽 정리는 파이프라인 글에 있다.

8. 069500이 14만 원? — 데이터를 의심하기 전에

위 작업 중 KODEX 200의 스윙 고점이 146,614로 나오는 게 눈에 걸렸다. 4~6만 원대라고 알고 있던 종목이라 컬럼 어순이 밀렸거나 다른 종목 데이터가 섞였다고 의심했다. 오판이었고, 데이터는 정상이었다. 확인 방법을 남겨 둔다.

-- ① 그 값이 실제로 있는가 (피벗은 최근 3년 주봉 종가에서 나온다)
SELECT target_date, close_price FROM stock_candle_daily
WHERE stock_code='069500' AND close_price BETWEEN 146000 AND 147000;

-- ② 어느 시점에 값이 튀는가 — 계단이 있으면 오염, 완만하면 진짜 시세
SELECT DATE_FORMAT(target_date,'%Y-%m') ym, MIN(close_price), MAX(close_price), COUNT(*)
FROM stock_candle_daily WHERE stock_code='069500' GROUP BY ym ORDER BY ym DESC;

-- ③ 같은 날짜 중복 행 — 주봉 거래량 합산이 왜곡된다
SELECT target_date, COUNT(*) c FROM stock_candle_daily WHERE stock_code='069500'
GROUP BY target_date HAVING c>1;

②는 2023-06의 약 32,000에서 2026-06의 148,056까지 끊김 없이 이어졌다. 컬럼 어순이 밀렸다면 반드시 계단이 생긴다. ③은 0건.

결정적인 건 외부 대조였다. **2026-09-02 코스피가 −3.99%(6,562.72)로 마감했는데, DB의 069500은 107,885 → 103,500 = −4.06%**였다. 화면의 레인지 위치 56%도 (103,500−40,900)/(152,148−40,900)으로 역산이 맞았다. 계산 경로 전체가 검증된 셈이다.

교훈은 이렇다. 자릿수가 낯설다는 이유로 데이터를 의심하기 전에 연속성·실제 지수 등락률·역산 세 가지를 먼저 본다. 2026년 코스피는 2,600에서 6,500 수준으로 올랐고 대표 ETF도 3배 넘게 올라 있었다. 내 기억이 낡은 것이었다.

10. 한계

  • 국면은 추정이고 후행 지표다. 추세가 바뀌는 시점을 미리 알려주지 못한다
  • ZigZag의 마지막 피벗은 아직 확정 전일 수 있다. 새 주봉이 쌓이면 고저점이 바뀐다
  • 임계값 경계(40/75, 60/25, 30/70) 근처에서는 판정이 흔들린다 — 화면에 52주 위치 %를 같이 노출하는 이유다
  • 대표 ETF는 지수 자체가 아니다. 추적오차·분배금만큼 다르다
  • 공통 Disclaimer 적용 대상이다

11. 같이 붙인 위젯 둘

같은 플로팅 층에 환율 위젯이 하나 더 있다. 야후 chart API(60초 캐시)로 환율 5종, 원자재 5종(금·WTI·브렌트·구리·은), BTC·ETH, 미국채 10년을 받아서 원본 시세만 보여 주는 게 아니라 파생 신호를 계산한다 — 금/구리 비율(안전자산 선호), 브렌트−WTI 스프레드(물류 병목), 엔캐리 청산 리스크 등급 같은 것들이다. 금리 쪽 화면은 국채·금리 페이지로 따로 나갔다.

홈 화면의 주요 지수도 원래 난수로 그리고 있었는데 실데이터로 바꿨다. 이 프로젝트에서 가장 많이 한 일이 그것이다 — 돌아보면.
