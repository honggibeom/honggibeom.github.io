2026.03.08 · #spring #spring-boot #java #백엔드 #로드맵

왜 지도부터 그리는가

Spring은 배울 게 많다기보다 경계가 흐려서 어렵다. "Spring을 공부한다"는 말 안에 자바 언어, 프레임워크 코어, 웹 계층, ORM, 트랜잭션, 보안, 배치, 배포가 전부 섞여 들어간다. 그래서 튜토리얼을 따라 CRUD 하나를 만들고 나면, 정작 "내가 뭘 아는지"를 스스로도 설명하지 못하는 상태가 된다.

그래서 지도를 먼저 그리기로 했다. 전체 범위를 주제별로 쪼개고, 주제마다 별도의 글에서 알아야 할 항목과 체크리스트를 정리한다. 이 글은 그 시리즈의 목차다.

원칙은 하나다. 순서를 건너뛰어도 되지만 0단계(자바)와 1단계(Core)를 건너뛰면 반드시 되돌아오게 된다. @Transactional이 왜 안 먹는지, 순환참조가 왜 나는지 같은 문제는 전부 그 두 단계에서 갈린다.

전체 지도

단계주제핵심 질문예상 기간
0자바 & 객체지향이 코드는 왜 이렇게 나뉘어 있나2~3주
1Spring Core (IoC/DI)내 객체를 누가 만들고 누가 넣어주나2주
2AOP와 프록시내가 안 짠 코드가 왜 끼어드나1주
3Spring MVC요청 하나가 어디를 거쳐 오나2주
4Spring Boot설정을 안 했는데 왜 동작하나1~2주
5데이터 계층 (JPA)객체와 테이블을 어떻게 맞추나4주+
6트랜잭션언제 커밋되고 언제 롤백되나1~2주
7Spring Security누가 요청했고 무엇을 할 수 있나2~3주
8테스트이 코드가 맞다는 걸 어떻게 증명하나2주
9Batch / 스케줄링대량 데이터를 어떻게 안전하게 돌리나2주
10운영 & 성능느려지거나 죽으면 어디를 보나지속

기간은 하루 2~3시간 기준의 대략치다. 실제로는 5단계(JPA)에서 시간의 절반을 쓴다.

시리즈 목차

각 주제는 개별 글로 따로 정리한다.

  1. [준비] 자바와 객체지향 — 인터페이스 의존, 예외 체계, 제네릭, 람다/Stream, 프록시 패턴, Gradle
  2. Spring Core: IoC 컨테이너와 의존성 주입 — 빈 등록·주입·스코프·생명주기, 순환참조
  3. AOP와 프록시 — 횡단 관심사, 포인트컷, JDK/CGLIB 프록시, self-invocation 함정
  4. Spring MVC — DispatcherServlet 흐름, 바인딩, 검증, 전역 예외 처리, REST API 설계
  5. Spring Boot — 자동 설정의 원리, 설정 파일과 프로파일, 스타터, 내장 톰캣
  6. Spring Data JPA — 영속성 컨텍스트, 연관관계, N+1, 페치 조인, QueryDSL
  7. 트랜잭션 — 전파 속성, 격리 수준, 롤백 규칙, @Transactional이 안 먹는 경우
  8. Spring Security — 필터체인, 인증/인가, JWT, OAuth2 소셜 로그인
  9. 테스트 — 단위/슬라이스/통합 테스트, Mockito, Testcontainers
  10. Spring Batch와 스케줄링 — Job/Step/Chunk, 재시작과 멱등성, @Scheduled, 락
  11. 운영과 성능 — Actuator, 로깅, 캐시, 비동기, 커넥션 풀, 배포

공부하는 방법에 대해

한 가지만 덧붙이면, 이 목록을 읽어서 끝내려고 하면 아무것도 남지 않는다. 각 단계마다 붙여둔 체크리스트는 "설명할 수 있는가"와 "직접 해봤는가"를 묻는 형태로 썼다. 문장을 눈으로 확인하는 게 아니라, 빈 에디터를 열고 그걸 재현할 수 있는지로 판단하는 게 맞다.

특히 다음 세 가지는 반드시 직접 깨뜨려보는 걸 권한다.

  • 순환 참조를 일부러 만들어서 에러 메시지 읽어보기
  • 같은 클래스 안에서 @Transactional 메서드를 호출해 트랜잭션이 안 걸리는 걸 확인하기
  • 연관관계를 지연 로딩으로 두고 N+1 쿼리를 로그로 직접 보기

이 셋을 겪고 나면 Spring이 마법이 아니라 프록시와 컨테이너로 이루어진 구조물이라는 게 보인다.

    Spring Boot 운영과 성능 정리. Actuator 모니터링과 로깅, 캐시와 비동기, 커넥션 풀과 JVM 설정, 배포까지 기능을 다 만든 뒤 실제로 손대게 되는 것들.

  • Spring Batch와 스케줄링 정리 - Job/Step/Chunk, 재시작, 멱등성, 분산 중복 실행 (Spring 로드맵 9)

    Spring Batch와 스케줄링 정리. 수십만 건 처리에 for문은 부족하다. Job/Step/Chunk 구조, 재시작과 멱등성, @Scheduled와 분산 환경의 중복 실행 문제까지 정리했다.

    Spring Security 정리. 설정을 외우는 방식으로는 반드시 막힌다. 필터체인 구조를 먼저 잡고, 인증과 인가를 나눈 뒤 JWT와 OAuth2 소셜 로그인으로 확장하는 순서로 정리했다.

    Spring @Transactional 정리. 전파 속성, 격리 수준, 롤백 규칙, 그리고 애노테이션을 붙였는데도 트랜잭션이 안 걸리는 대표적인 경우(내부 호출, 체크 예외, 프록시)를 정리했다.
